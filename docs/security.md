# Security boundaries

## Independent local model runtime

- `arena-computer-agent` is a local CLI. Its controller client accepts only an HTTP loopback origin; the agent does not create a listener, public URL, or tunnel. The controller remains bound to loopback by default and refuses a non-loopback bind without a bearer token.
- The model API key is read from `ARENA_MODEL_API_KEY` and sent only in the provider's HTTPS `Authorization` header. It is not placed in source, model messages, or progress output. Redirects are disabled so the API key is not forwarded to a redirect destination. Provider errors do not echo response bodies or credentials. Keep the API key out of terminal recordings and screenshots.
- The controller bearer token, when configured, is separate. It is used only for local loopback controller requests and is never placed in the model conversation.
- By design, task text, the controller's returned state, model tool calls, tool results, and any requested screenshot bytes are sent to the configured model provider. Screenshot image bytes are base64-encoded as a real image input in the HTTPS model request; they are not reduced to a path or hash. A desktop screenshot or state may contain private information. Use only a provider/workspace approved for that data, review its retention and billing terms, and avoid requesting screenshots of sensitive windows.
- Screenshot capture is on demand. The existing bridge validates image type/size and suppresses byte-identical repeats unless forced. The provider adapter caps request and response sizes and has a configurable timeout; the runtime does not write model conversations or screenshots to persistent storage.
- The agent currently exposes only the existing six state/screenshot/Blender tools. Blender execution is separately gated by a console approval prompt and revalidated against the existing allowlist/request-ID path. The agent has no arbitrary shell/Python tool, and general Windows click/type actions are not currently exposed as model tools.
- `ARENA_MODEL_BASE_URL` is configurable for compatible providers. Remote providers must use HTTPS; plain HTTP is allowed only for localhost testing. The owner is responsible for selecting a trusted endpoint. Account access, model availability, image support, and usage cost must be verified in that provider account.

## Preserved Phase 3 controls

- Service binds to `127.0.0.1`; never expose or port-forward it. `GET /health` is unauthenticated and contains no project data.
- `CONNECTOR_TOKEN` is required by the Studio plugin routes. `CONNECTOR_EXTENSION_TOKEN` is a separate secret for the extension-facing routes. Both must be at least 32 characters and must differ. Comparisons use timing-safe equality for equal-length values. Secrets are never logged.
- The plugin token remains a local shared secret; `plugin:SetSetting` is convenient, not a documented encrypted vault. The extension token is kept in the user's browser extension storage, not in page DOM, a content-script message, or an assistant-visible prompt. Browser profile/extension compromise can still expose it; rotate it if needed.
- A new plugin session gets a cryptographically random UUID. Each heartbeat must match the active ID. New registration replaces the old one; heartbeat expiry is 15 seconds. Old/stale IDs cannot refresh the active session.
- Bodies and serialized responses are capped at 8 KiB; the overview uses an exact key contract, service allowlist, unique entries, bounded counts, and type checks. Server request/header timeouts are set. No conversation data is stored or read by the connector.

## Phase 4B mutation boundary

- The extension is restricted to Arena Direct/conversation URLs and loopback connector origin. The worker accepts only its own content-script messages from `https://arena.ai/text/*` or `/c/*`, validates the exact operation and UUID, and never exposes token data to the page context. The extension's optional prompt suffix contains only the schema and explicit instruction that user approval is required.
- The content script reads only new assistant response `<pre>` blocks after the user enables the feature, and only when the block is visibly rendered (not hidden/ARIA-hidden and intersecting the viewport). Repeated references to the same node are deduplicated; nested nodes collapse only when their parsed typed command is exactly equal. Distinct visible commands and conflicting nested commands fail closed. It waits for the response text and code-block/render signature to remain stable after generation ends. It extracts a single bounded delimited JSON command; it sends only `{requestId, operation, name}`. It does not upload a transcript, user prompt, model name, unrelated DOM, or other page data.
- The server extension token can enqueue and inspect a typed command, but it cannot call the Studio decision/result routes. Those require the separate Studio token and an operation-specific approval capability delivered only in the authenticated Studio heartbeat. The queue rejects duplicate IDs, expires after 60 seconds, is bounded, and requires an active Studio heartbeat.
- The Studio plugin independently validates the operation name before displaying a pending request: it must be a nonempty string of at most 40 characters, already trimmed, containing only ASCII letters, digits, spaces, `_`, or `-`. It does not normalize invalid names. The Studio plugin displays the exact validated operation values and fixed `Workspace` target, then requires an explicit Approve or Reject click for every mutation. `create_test_folder` creates exactly one Folder. `create_part` creates exactly one basic Part with bounded name, position, size, integer RGB, allowlisted material, `Anchored`, and `CanCollide`; it exposes no parent/class/rotation selection. Both use a request-ID attribute for safe retry detection and reject name collisions without overwriting. No assistant-provided JS/Lua, arbitrary instance paths, scripts, or other operations are accepted.
- Result delivery is a minimal operation status/name. The extension may place that status into an Arena composer draft only after a user click; it never auto-sends a success claim.
- Server state is in-memory; restart loses session, queue, and result status. The prototype does not promise durable recovery across server/Studio restarts.

## Remaining risks and verification

The Arena DOM selectors and response-completion signal come from a third-party provider that reports validation on Arena Direct in June 2026. This agent had no live browser/DOM to verify the October 2026 page, and the local-LAN permission behavior varies by browser. DOM changes may make the feature stop detecting responses; fail-closed behavior should prevent fallback to broad scraping. Verify the actual browser path before trusting it. The extension's local token is not encrypted, and a compromised browser profile/extension or local machine is outside this prototype's protection boundary.

The first Windows end-to-end `create_test_folder` smoke test succeeded. The new `create_part` operation still requires a separate Windows Studio retest. No public listener, CORS-based trust, remote relay, shell, filesystem operation, arbitrary Luau execution, or automatic project mutation without Studio approval is included.
